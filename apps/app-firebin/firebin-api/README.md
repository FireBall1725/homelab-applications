# firebin-api

> Go backend for the self-hosted FireBin electronics parts inventory

## Overview

FireBin tracks electronics parts: quantity, package, brand, location, and vendor pricing, with distributor-bag scanning and bin/part label printing. This chart deploys the Go API and its CloudNative-PG managed PostgreSQL cluster. The companion [`firebin-web`](../firebin-web/) chart serves the UI and reverse-proxies `/api` back to this service.

The container listens on `:8080` and runs its own database migrations on start. This chart follows the `librarium-api` pattern (common library, CNPG cluster, SealedSecret for the session key).

## Service name is load-bearing

`fullnameOverride: firebin-api` fixes the Service to `firebin-api` on port 8080. The `firebin-web` image's bundled nginx proxies `/api` to `http://firebin-api:8080` by bare service name, so this Service must keep that name and both charts must deploy into the same namespace (`app-firebin`).

## Ingress

None. `firebin-web` is the only public entrypoint. Exposing the api directly would bypass the web tier's `/api` proxy and is not needed.

## Persistence

| Volume | Size | Storage Class | Notes |
|--------|------|---------------|-------|
| `firebin-api-attachments` | 10Gi | `longhorn` | Datasheets and part images (RWO), mounted at `/app/data/attachments` |
| `firebin-db` (CNPG) | 10Gi | `longhorn` | PostgreSQL cluster, PG 17.2-3 |

The api reads `ATTACHMENT_STORAGE_PATH` (set to `/app/data/attachments`) for the on-disk attachments location.

## Secrets

Uses [Sealed Secrets](../SECRETS.md) for sensitive values.

| Secret | Contents | Source |
|--------|----------|--------|
| `firebin-api-jwt` | `JWT_SECRET` (session signing key) | SealedSecret (`templates/sealed-secret-jwt.yaml`) |
| `firebin-db-app` | PostgreSQL DSN (`uri` key) | Auto-generated by CNPG operator |

`JWT_SECRET` is a generated random value sealed for `app-firebin`. Keep it stable; changing it logs everyone out. `DATABASE_URL` is pulled from the CNPG `firebin-db-app` secret (`uri` key).

### Digi-Key enrichment (optional)

Enrichment pulls datasheets, parameters, images, and price breaks from the Digi-Key V4 API. Two ways to supply the credentials:

1. **UI (recommended):** enter the client ID and secret under Settings, Enrichment. They are stored in the database and survive restarts.
2. **Env via a sealed secret:** seal a `firebin-api-enrichment` secret, then uncomment the `DIGIKEY_*` env block in `values.yaml`:

   ```bash
   kubectl create secret generic firebin-api-enrichment \
     --namespace=app-firebin \
     --from-literal=DIGIKEY_CLIENT_ID='...' \
     --from-literal=DIGIKEY_CLIENT_SECRET='...' \
     --dry-run=client -o yaml | \
     kubeseal --controller-namespace kube-system --format yaml \
     > firebin-api/templates/sealed-secret-enrichment.yaml
   ```

## Registration

`REGISTRATION_ENABLED` is `false`. The first account registered through the web UI still bootstraps the admin (first-run setup wizard); open self-signup stays closed after that. Set it to `"true"` only to allow anyone on the LAN to create their own account. The `*.k8s.firekatt.ca` zone resolves inside the LAN only.

## Notes

- PostgreSQL is provisioned via a `Cluster` CR managed by [CloudNative-PG](../cloudnative-pg/).
- Liveness and readiness probes hit `GET /api/v1/health` on `:8080` (public, no auth, no DB dependency; returns status and version).
